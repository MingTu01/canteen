## 1. 项目定位

食堂现场 X86 触屏一体机专用程序,分**订餐终端**与**取餐终端**两种固定设备。
采用「**Tauri 全屏运行 + 隐藏管理入口**」架构:

- **运行模式**(面向员工,日常运行):开机自启,**默认全屏无边框**,按配置的模式**固定**显示订餐或取餐界面,**运行中不可切换模式、不可随意退出**(防误操作)
- **管理模式**(管理员使用,隐藏入口触发):连续点击窗口右上角 6 下 → 密码验证 → 选择「配置模式 / 退出 / 取消」
- 一台设备 = 一种模式,不混用

### 关键特性
- 开机自启动、不可退出(Tauri 全屏锁定 + 部署层系统服务)
- 适配多触屏、多分辨率
- 适配多种型号读卡器(USB HID 模拟键盘 + 内置 CH372 驱动)
- 适配多种型号摄像头(扫码取餐)
- **Tauri 桌面壳**:轻量级原生外壳,替代 Electron,体积更小、启动更快
- **配置文件支持注释**:EXE 同目录的 `config.json` 支持 `//` 行注释,便于运维填写

## 2. 适配规范

| 维度 | 规范 |
|---|---|
| 显示 | 全屏触屏,多分辨率自适应。设计稿基于横屏,用等比缩放(`transform: scale` 或 `vw/rem`)保证不同分辨率下布局比例一致 |
| 触屏 | 用 Pointer Events,同时支持触摸与鼠标;按钮尺寸 ≥ 44px,间距充裕 |
| 读卡器 | USB HID 读卡器均模拟键盘:监听 `keydown` 序列,以回车结束 = 一个卡号。统一一个全局键盘监听器捕获,适配所有型号。**禁止**用 `prompt()`/`input` 拦截,用隐藏焦点监听 |
| 摄像头 | `navigator.mediaDevices.getUserMedia` 调用摄像头 + `jsQR`(或 zxing-js)解码二维码取餐码。设备选择:默认后置,失败可切换 |
| 字体/主题 | 与 H5 一致:浅色白底,`system-ui`,圆角 1.2rem,primary `#0065fd`。**不出现深色主题** |
| 配色 | 与 H5 需求书相同的 doubao 变量集 |

## 3. 管理入口与配置程序(管理员)

### 3.1 隐藏管理入口(运行模式 → 管理模式)

运行模式下界面无任何管理按钮,**连续点击窗口右上角 6 下**(2 秒内)触发:

```
连续点击右上角 6 下
       ↓
弹出密码输入框(居中模态)
       ↓
输入管理员密码 → 与 config.json 中的 admin_password_hash (SHA256) 比对
       ↓
验证通过 → 弹出三按钮操作菜单
       ↓
┌──────────────┬──────────────┬──────────────┐
│   配置模式    │     退出      │     取消      │
│ 退出全屏      │ 关闭整个应用   │ 返回运行模式   │
│ 进配置页      │              │              │
└──────────────┴──────────────┴──────────────┘
```

- **配置模式**:调用 Tauri 命令 `switch_to_config_mode`(退出全屏 + 显示窗口装饰 + 允许调整大小)→ 跳转 `/settings`
- **退出**:调用 Tauri 命令 `quit_app` 关闭整个应用
- **取消**:关闭弹窗,回到运行模式
- 密码错误有提示,可重试;点击遮罩或取消按钮可关闭

### 3.2 配置程序(Settings.vue)

首次启动 / 未配置时直接进入配置界面;管理员通过隐藏入口触发后亦可再次进入:

- **未绑定** → 配置界面:
  - 服务器域名(留空 = 同源走代理;生产填绝对地址;config.json 预设的 `server_url` 会自动填入)
  - 管理员账号 + 密码
  - 食堂安全码
  - 模式:**订餐终端** 或 **取餐终端**(单选,定死)
  - 设备标识(可选)
- 「测试并绑定」:调 `POST /api/terminal/bind` 双重校验(管理员账号密码 + 食堂安全码,storeId 一致)→ 签发终端 token(role=3, storeId 锁定)→ 保存配置 → 进入运行模式
- **已绑定**:展示绑定信息、切换运行模式、进入运行模式、解除绑定(管理员密码二次校验)
- 解绑/重配成功后覆盖旧配置

## 6. 鉴权与数据隔离

- 终端 token:role=3,storeId 锁定(绑定签发,见配置程序)
- 刷卡识别:`GET /api/terminal/employee/{cardNo}` 从 token 取 storeId 查本店员工,**不签发员工 token**,门店隔离不被破坏
- 菜单:`GET /api/menu/store/{storeId}/date/{date}`
- 下单:`POST /api/order`(body 含 storeId/employeeId/date/mealType/items)
- 取餐扫码:`POST /api/order/pickup {pickupCode}`
- 完成取餐:`PUT /api/order/{id}/complete`
- 取消:`DELETE /api/order/{id}`
- 跨店访问:role=3 token 锁 storeId,后端 `SecurityContext` 校验

## 8. 预览与部署

- **预览**:与 H5 共用一个端口,按路径区分。终端挂在 `/terminal/*`
- **生产部署(Tauri 桌面应用)**:
  - 程序打包为 Tauri 原生 EXE(`src-tauri/dist-portable/canteen-terminal.exe`),绿色免安装
  - EXE 同目录放置 `config.json`(支持注释)配置管理员密码哈希和预设服务器地址
  - **默认全屏无边框启动**,面向员工日常使用;管理员通过右上角 6 次点击进入配置模式
  - 开机自启:将 EXE 路径加入 Windows 启动项(注册表 `HKCU\...\Run` 或启动文件夹)
  - 不可退出:全屏无边框模式无关闭按钮;管理员通过隐藏入口 `quit_app` 退出
  - **CH372 读卡器驱动**:已预装于 `src-tauri/drivers/CH372/`,支持 VID_4348&PID_5537/VID_1A86&PID_5537/VID_1A86&PID_5576 等多种芯片;首次部署时运行 `读写器驱动安装32or64bit.exe` 安装

### 8.1 config.json 配置说明

EXE 同目录的 `config.json`(支持 `//` 行注释):

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `admin_password_hash` | string | "admin" 的 SHA256 | 管理员密码的 SHA256 哈希(十六进制小写,64 字符),用于右上角 6 次点击后的密码验证 |
| `server_url` | string | "" | 预设后端服务器地址,绑定页面会自动填入;留空则要求手动输入 |

密码哈希生成方法(任选其一):
- 浏览器控制台:`crypto.subtle.digest('SHA-256', new TextEncoder().encode('你的密码')).then(b=>console.log([...new Uint8Array(b)].map(x=>x.toString(16).padStart(2,'0')).join('')))`
- Python:`python -c "import hashlib;print(hashlib.sha256('你的密码'.encode()).hexdigest())"`
- 在线工具:https://emn178.github.io/online-tools/sha256.html

## 9. 已确认决策

1. **管理入口解锁方式**:**连续点击窗口右上角 6 下**(2 秒内)→ 弹管理员密码框 → 验证通过显示三按钮菜单(配置模式/退出/取消)
2. **默认运行模式**:**全屏无边框**,不再区分"配置程序/运行程序"两种启动方式,统一为运行模式 + 隐藏管理入口
3. **读卡器**:全部 USB HID(模拟键盘),统一全局键盘监听器捕获,回车结束 = 一个卡号;内置 CH372 驱动(VID_4348&PID_5537)
4. **扫码取餐**:摄像头扫描**员工身份二维码**(JSON 含签名),不是订单核销码。扫码等同刷卡,拿到 cardNo 后走 `/pickup/verify`
5. **无操作自动回待机**:**默认 60 秒**无操作自动回待机页(选菜/查询/取餐信息等页适用)
6. **开机自启 + 不可退出**:Tauri 全屏无边框锁定 + 提供部署说明(系统侧配置自启)
7. **分辨率**:17 寸触摸屏,1280×1024 基准(等比缩放适配其他分辨率)
8. **桌面壳**:采用 **Tauri**(替代 Electron),体积更小、内存占用更低、原生 WebView 性能更好

## 10. 扫码取餐流程(对照设计稿 [取餐终端] 待机首页.html「扫码取餐」入口)

取餐终端待机页两个入口:
- **刷卡取餐**:全局键盘监听 → cardNo
- **扫码取餐**:摄像头扫员工身份二维码 → 解析 JSON → 取 cardNo

两者拿到 cardNo 后流程统一:
```
拿到 cardNo
   ↓
GET /api/terminal/employee/{cardNo}  (终端 token,storeId 锁定)
   ↓
命中本店员工 → /pickup/verify(验证中,查今日订单)
   ↓
/pickup/info(取餐信息页,30秒倒计时)
   ↓
点「取餐完成」→ PUT /api/order/{id}/complete → 回待机
```

### 二维码内容(与 H5 需求书第 8 节一致)
```json
{
  "cardNo": "CARD001",
  "storeId": 1,
  "employeeId": 1,
  "name": "张明",
  "expire": 1800000000000,
  "sign": "HMAC-SHA256 前16位"
}
```

### 终端扫码校验
- 用 `jsQR` 解码摄像头帧 → 解析 JSON
- 校验 `sign`(用终端 token 内的 storeId + 后端公钥/共享密钥验签;若终端不存密钥,可改为扫码后直接传 JSON 给后端校验)
- **建议简化方案**:终端扫码只取 `cardNo`,直接调 `/terminal/employee/{cardNo}`(后端已按 token 的 storeId 隔离),签名校验由后端在新增的 `POST /api/terminal/verify-qrcode` 接口完成。终端无需密钥,更安全
- 校验 `expire` 未过期
- 二维码非本店员工 / 已过期 / 签名错误 → 提示「无效二维码」回待机

### 后端新增
- `POST /api/terminal/verify-qrcode` body: `{qrcodeJson: string}` → 校验签名+过期+门店 → 返回员工信息(或终端直接用 cardNo 调现有 `/terminal/employee/{cardNo}`)

## 11. 自动回待机机制

- 全局活动监听(触摸/鼠标/键盘),有活动重置 60 秒计时器
- 计时器归零 → 跳对应模式的待机页(`/order` 或 `/pickup`),清空当前员工/订单状态
- 取餐信息页的 30 秒倒计时与此独立(取餐信息页本身就有 30 秒返回逻辑)
