## 1. 项目定位

面向员工的手机端订餐入口,以 H5 形式承载(后续可套壳为微信小程序)。
员工通过**手机号 + 密码**登录,系统**自动定位其所属食堂**,无需手动选择食堂。

- 使用场景:手机浏览器 / 微信内访问 / 桌面浏览器(居中手机容器)
- 鉴权:员工 token(role=0),JWT 携带 storeId,数据按门店隔离

## 4. 登录鉴权流程(核心改动)

```
用户输入手机号+密码
        ↓
POST /api/employee/phone-login  body: { phone, password }   ← 不传 storeId
        ↓
后端:selectByPhone(phone) 全局唯一查询 → 命中员工(含 storeId)
        ↓
校验密码(BCrypt) → 签发 token(role=0, storeId, employeeId)
        ↓
返回 { token, employee:{id,name,phone,cardNo,storeId,balance,departmentName} }
        ↓
前端存 token + employee → 跳 /
```

- 前端路由守卫:无 token → `/login`;有 token 访问 `/login` → `/`
- 所有业务请求带 token,后端按 storeId 隔离

## 8. 员工身份二维码(取餐扫码用)

个人中心展示员工身份二维码,供取餐终端摄像头扫描(等同刷卡)。

- **内容格式**:JSON,含签名防伪
  ```json
  {
    "cardNo": "CARD001",
    "storeId": 1,
    "employeeId": 1,
    "name": "张明",
    "expire": 1800000000000,
    "sign": "xxxxxxxx"
  }
  ```
- **签名算法**:`sign = HMAC-SHA256(后端密钥, cardNo + "|" + storeId + "|" + employeeId + "|" + expire)` 取 hex 前 16 位
- **后端新增接口**:
  - `GET /api/employee/my-qrcode`:用当前登录员工信息 + 后端密钥生成签名,返回完整 JSON 内容(不直接返图,前端用 qrcode 库渲染)
- **前端**:个人中心调用该接口拿 JSON 字符串,用 `qrcode` npm 包生成二维码图片展示
- **有效期**:`expire` = 当前时间 + 7 天,二维码每周刷新;终端扫码时校验未过期
- **脱敏**:二维码区域默认模糊显示,点击长按才清晰(防截屏,可选)
