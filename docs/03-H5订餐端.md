## 1. 项目定位

面向员工的手机端订餐入口，以 H5 形式承载（后续可套壳为微信小程序）。员工通过**手机号 + 密码**登录，系统**自动定位其所属食堂**，无需手动选择食堂。

- **使用场景**：手机浏览器 / 微信内访问 / 桌面浏览器（居中手机容器）
- **鉴权**：员工 token（role=0），JWT 由后端写入 HttpOnly Cookie，数据按门店隔离
- **缓存策略**：菜品图片 + 登录用户头像（IndexedDB，30 天 TTL，版本化 URL 失效）
- **服务器时间同步**：所有时间判断以后端为准，防本机时间篡改

## 5. 图片缓存策略（核心需求）

> **用户需求**：H5 要缓存菜品图片和登录过的个人头像

### 5.1 缓存范围

| 缓存对象 | 缓存策略 | 说明 |
|----------|----------|------|
| **菜品图片** | 懒加载 + IndexedDB | Home 今日新品 + Order 菜单页菜品卡片 |
| **当前登录用户头像** | 懒加载 + IndexedDB | Profile.vue 通过 watch employee.avatar 调用 getCachedImage |
| 其他员工头像 | **不缓存** | 与 X86 终端的"全量头像缓存"策略区分 |

### 5.2 IndexedDB Schema

- **DB 名**：`canteen_image_cache`（version 1）
- **Object Store**：`images`（无 keyPath，使用 out-of-line key）
- **Key 生成策略**：URL 解析后的 **pathname（去掉 `?v=` 查询参数）**
- **Value 结构**：`{ blob: Blob, version: string, timestamp: number }`

### 5.3 版本与失效策略

**版本号**：URL 中的 `?v=mtime` 参数（后端用文件 mtime 生成版本号）

**三重校验**：
1. **版本号匹配**：`getCache` 时若 `version && entry.version && entry.version !== version` 则视为失效，重新 fetch
2. **TTL**：30 天（`30 * 24 * 60 * 60 * 1000`），超过自动清理
3. **路径过滤**：只缓存 `/uploads/` 路径，`data:`/`blob:` URL 直接返回；非本 host 的绝对 URL 仅当包含 `/uploads/` 才缓存

### 5.4 缓存键生成（parseUrl）

```ts
function parseUrl(url: string): { path: string; version: string }
```
- 使用 `new URL(url, window.location.origin)` 解析
- `path = u.pathname`（纯路径，无查询参数）
- `version = u.searchParams.get('v') || ''`
- 解析失败回退为 `{ path: url, version: '' }`

### 5.5 getCachedImage 流程

1. 空 URL / `data:` / `blob:` URL 直接返回
2. 非 `window.location.host` 的绝对 URL：仅当包含 `/uploads/` 才缓存
3. `parseUrl` 拆分 path + version
4. path 不以 `/uploads/` 开头则不缓存，直接返回原 URL
5. `getCache(path, version)`：命中且版本匹配且未过期 → 返回 `URL.createObjectURL(blob)`
6. 未命中：`fetch(url)` → `resp.blob()` → 仅 `image/*` 类型才 `setCache` → 返回 blob URL
7. fetch 失败回退原 URL（静默处理）

### 5.6 清理时机
- `main.ts` 启动时调用 `cleanExpiredCache()`，遍历 cursor 删除超期项

### 5.7 调用点
- `Home.vue`：`refreshDishImages()` 批量预加载今日新品到 `cachedDishImages` Map
- `Order.vue`：`refreshDishImages()` 批量预加载所有日期菜单菜品图片
- `Profile.vue`：`watch(employee.avatar)` 单个头像缓存到 `avatarSrc`

## 6. 登录鉴权流程

### 6.1 登录方式

- **H5 主登录**：手机号 + 密码（`POST /api/employee/phone-login`，无 storeId，因手机号全局唯一）
- 卡号登录（`login(cardNo, storeId, password)`）：需指定门店（卡号可能跨店重复），H5 端主要走手机号登录
- **测试快速登录**（Login.vue）：从 `/api/test/employees` 拉取员工列表，点击员工用 `phone + '123456'` 模拟登录（始终显示，便于部署演示）

### 6.2 登录流程

```
用户输入手机号+密码
        ↓
POST /api/employee/phone-login  body: { phone, password }   ← 不传 storeId
        ↓
后端: selectByPhone(phone) 全局唯一查询 → 命中员工(含 storeId)
        ↓
校验密码(BCrypt) → 签发 token(role=0, storeId, employeeId) → 写入 HttpOnly Cookie
        ↓
返回 { employee:{id,name,phone,cardNo,storeId,balance,departmentName} }
        ↓
前端存 employee → localStorage → 跳 /
```

### 6.3 Token 存储

- **token 不存前端**：由后端写入 **HttpOnly Cookie**（`auth_token`），浏览器自动随请求带上
- `withCredentials: true` 必需
- **employee 信息** → `localStorage`（key: `canteen_h5_employee`），刷新页面后恢复用户信息
- **isLoggedIn 标志** → `sessionStorage`（key: `canteen_h5_logged_in`），关闭浏览器标签后失效需重新登录

### 6.4 登录后刷新头像（硬约束）

> **H5 必须刷新员工头像数据后登录，避免 stale localStorage 值**

- `authStore.phoneLogin` 返回 employee 后持久化到 localStorage
- `Profile.vue` onMounted 调用 `authStore.refreshEmployee()`（从后端 `GET /employee/{id}` 拉取最新余额、头像等）
- `refreshEmployee` 内部：`getEmployee(id)` → 更新内存 + 重新持久化 localStorage

### 6.5 路由守卫

- 无 token → `/login`（带 redirect query）
- 有 token 访问 `/login` → `/`

### 6.6 401 处理

- 响应拦截器统一处理：HTTP 200 + code=401 或 HTTP 401
- **401 并发去重**：`isRedirecting` 标志，多个并发 401 只允许第一个触发清理+跳转
- **登录请求特殊处理**：登录失败不清状态/跳转，仅 toast 提示
- `clearAuthAndRedirect`：动态 import 规避循环依赖，先清 auth/branding/cart store，再 `router.push('/login?redirect=...')`

### 6.7 注销流程

```
logout():
  1. await authApi.logout()  // POST /auth/logout，后端清 Cookie + token 加入黑名单（即使失败也继续清前端）
  2. employee.value = null
  3. isLoggedIn.value = false
  4. persistEmployee(null)  // 移除 localStorage
  5. persistLoggedIn(false) // 移除 sessionStorage
```

`Profile.vue` onLogout：logout 后额外调用 `brandingStore.clearBranding()` + `cartStore.clearAll()` + 清空取餐码缓存，避免跨用户泄漏。

## 7. 服务器时间同步（useServerTime）

### 7.1 为什么用服务器时间

> 统一从后端 `/api/system/time` 获取时间，**避免本机时间篡改绕过限制**。

员工若改手机时间可绕过"过点不订"等校验，故必须以服务器时间为准。

### 7.2 接口

`GET /api/system/time`（白名单接口，不需要鉴权，用独立 axios 实例 `rawApi`，baseURL `/api`）

返回 `ServerTime`：
- `timestamp`（毫秒时间戳）
- `date`（yyyy-MM-dd，Asia/Shanghai）
- `time`（HH:mm，Asia/Shanghai）
- `minutes`（当前小时*60+分钟，便于过点不订判断）
- `datetime`（ISO LocalDateTime）

### 7.3 三层时间获取

1. **fetchServerTime(force)**：5 秒内不重复请求，命中缓存则用 `estimateCurrent()` 估算；否则请求后端，失败回退本机时间（`useFallback=true`，失去防篡改能力）
2. **estimateCurrent()**：基于上次拉取的 `cachedTime.timestamp + (Date.now() - lastFetchAt)` 估算当前服务器时间，转 Asia/Shanghai 时区，避免每次调用都发请求
3. **useServerTime()**：响应式 composable，`start()` 拉取一次后 `setInterval(estimateCurrent, 1000)` 每秒更新，`stop()` 清理定时器

### 7.4 调用点
- `UnsolicitedOrder.vue`：onMounted 并行加载服务器时间 + 餐别时段，每 30 秒刷新一次，下单前 `fetchServerTime(true)` 强制刷新避免过期

## 8. 品牌信息 Store（branding）

### 8.1 数据
`Branding` 接口：`id`、`name`、`logoUrl`、`imageUrl`、`terminalBackgroundUrl`、`h5BannerUrl`、`description`、`updatedAt`

### 8.2 ETag 304 缓存策略（零带宽优先）

- **localStorage 持久化**：key 按门店隔离 `canteen_h5_branding_{storeId}`，存储 `{ etag, data }`
- **秒开**：有缓存则先用缓存渲染，后台异步校验
- **请求**：`getBranding(storeId, etag)` 带 `If-None-Match` header，`validateStatus` 接受 304
  - **304**：数据未变，保留缓存（零带宽，无 body）
  - **200**：更新内存 + localStorage + etag
  - **网络错误**：回退到缓存
- 使用 `_raw: true` 标记绕过业务拦截器，返回完整 AxiosResponse 供读取 ETag header

### 8.3 清理
- `clearBranding()`：清所有 `canteen_h5_branding_*` 开头的 localStorage key + 内存状态
- 调用时机：切换门店、登出、401 拦截

## 9. 购物车 Store（cart）

### 9.1 数据结构
- **items**：`Map<groupKey, Map<dishId, CartEntry>>`
  - `groupKey = ${date}|${mealType}`（跨日期 + 按餐次分组）
  - 内层按 dishId 索引，值为 `{ dish, quantity }`
- **selectedDate**：当前查看的菜单日期（用于左侧日期栏高亮 + 右侧菜单加载），不再绑定购物车内容

### 9.2 跨日期订餐
- 切换 selectedDate **不清空购物车**，下单时遍历所有 group 依次提交
- **不持久化**：每次打开 H5 重新选菜

### 9.3 关键方法
- `addItem(dish, date, mealType)`：含单次限购校验（`dish.maxPerOrder > 0` 时生效），超限 toast
- `getAllGroups()`：返回 `CartGroup[]`，按日期升序、同日期按餐别升序排序
- `dateHasItems(date)` / `getMealTypesForDate(date)`：用于日期竖列的三餐色圆点提示

### 9.4 结算流程（Order.vue doSubmit）

1. 校验购物车非空 + storeId/employeeId 存在
2. **余额检查**：`balance < total` 则 toast "余额不足，请联系管理员充值"
3. `getAllGroups()` 拉平为 (date, mealType) 列表，**逐个调用 `createOrder(dto)`**
4. 每组成功记录 key 到 `successKeys`，失败收集到 `errors`
5. 清空已成功 group（`clearGroup`）
6. `authStore.refreshEmployee()` 刷新余额
7. 全部成功 → showSuccessToast + 1 秒后跳 `/orders`；部分成功 → toast 错误列表 + 1.5 秒跳转；全失败 → toast 错误
8. `navTimer` 在 onDeactivated/onBeforeUnmount 清理，避免离开页面后被意外导航

### 9.5 下单确认弹窗
- 点击"去结算"先打开 `showSubmitConfirm` 确认弹窗（树形结构：日期→餐别→菜品），确认后才真正 `doSubmit`

## 10. Order.vue 订餐页关键特性

- **单页堆叠模式**：所有可订餐日期同时渲染在 DOM 中，上下滚动自然浏览，无"切换日期"动作
- **并发加载菜单**：`loadAllMenus` 并发上限 5（滑动窗口 worker 模式），加载完成后 `allMenusLoaded=true` 统一渲染，杜绝懒加载布局抖动
- **过点不订**：`isMealOrderable` 判断当前时间 < 餐别 endTime；明天受 15 点截止限制（`ORDER_DEADLINE_HOUR=15`）
- **已下单锁定**：`fetchOrderedOrders` 拉取 status=1 订单，锁定已订餐别（禁止加菜），已订菜品显示绿色 ✅ + 份数
- **图片懒加载**：IntersectionObserver（rootMargin 下扩 100%）控制 `<img>` 渲染，未激活显示 emoji 占位不发请求
- **日期竖列**：7 天（今天为中心前后各 3 天），每项显示日期 + 星期；选中项 primary 背景 + 白字 + 右上角小圆点（表示当日有订餐）

## 11. 员工身份二维码（取餐扫码用）

个人中心展示员工身份二维码，供取餐终端摄像头扫描（等同刷卡）。

### 11.1 内容格式

```json
{
  "cardNo": "CARD001",
  "storeId": 1,
  "employeeId": 1,
  "name": "张明",
  "expire": 1800000000000,
  "sign": "HMAC-SHA256 前16位"
}
```

### 11.2 签名算法
`sign = HMAC-SHA256(后端密钥, cardNo + "|" + storeId + "|" + employeeId + "|" + expire)` 取 hex 前 16 位

### 11.3 后端接口
- `GET /api/employee/my-qrcode`：用当前登录员工信息 + 后端密钥生成签名，返回完整 JSON 内容（不直接返图，前端用 qrcode 库渲染）

### 11.4 前端实现
- `qrcode` 库的 `QRCode.toDataURL(content, { width: 240, margin: 1 })`
- **有效期**：7 天（UI 提示"有效期7天，可在取餐终端扫码使用"）
- **过期判断**：`isQrcodeExpired()` 比较 `Date.now() > expire * 1000`

### 11.5 展示位置（Profile.vue）
1. **内嵌卡片**：用户卡下半部分，200×200px 缩略图（可直接扫描识别），点击放大
2. **放大弹层**：居中 popup，240×240px，显示二维码 + 姓名 + 卡号 + 有效期提示
3. onMounted 自动加载（不弹层），供内嵌卡片展示

### 11.6 退出登录清理
- onLogout 中 `qrcodeData.value = null; qrcodeImg.value = ''`，避免下一用户看到上一用户的二维码

## 12. 未订餐用餐流程（UnsolicitedOrder）

### 12.1 业务场景
员工未提前订餐，到现场加餐。需打菜人员确认菜品后下单。

### 12.2 服务器时间判定当前餐别
- onMounted 并行加载：`fetchServerTime()` + `getDiningTimes(storeId)`
- `currentMealType` computed：
  1. 优先匹配有时段配置的餐别（`nowMin >= startMin && nowMin < endMin`）
  2. 无匹配时按固定规则：11 点前早餐、11-16 午餐、其他晚餐
- 每 30 秒 `setInterval` 刷新服务器时间
- **下单前 `fetchServerTime(true)` 强制刷新**，避免下单时时间已过期

### 12.3 仅展示当前餐别菜品
- `currentMenu` computed：从今日菜单 `menus.value.find(m => m.menu.mealType === currentMealType)`
- 其他餐别菜品不可选

### 12.4 绕过后端校验（orderSource=1）

```ts
await createOrder({
  storeId, employeeId,
  date: today,           // serverTime.date
  mealType,              // 当前餐别
  items: [...],
  orderSource: 1,        // 未订餐用餐
})
```

- `orderSource=1` 通知后端绕过：
  - **截止时间校验**（过点不订）
  - **防重复校验**（同日同餐别已订）

### 12.5 交互流程
1. 进入页面 → 加载服务器时间 + 餐别时段 + 今日菜单
2. 显示当前餐别 + 服务器时间 + 日期信息卡
3. 提示"下单前请打菜人员确认菜品"
4. 选菜（含单次限购校验 `maxPerOrder`）
5. 点击"确认下单" → `showConfirmDialog`（标题"请打菜人员确认"）
6. 确认后 `createOrder(orderSource=1)` → showSuccessToast → 1.5 秒后跳 `/orders`
7. onUnmounted 清理 30 秒定时器

## 13. Orders.vue 订单列表特性

- **状态 Tab**：全部/待取餐/已完成/已取消（computed 过滤，不重新请求）
- **日期分组**：正序（过去→今天→未来），今天即使无订单也插入占位锚点
- **餐别分组**：同一餐别所有订单菜品合并平铺展示
- **取餐码**：待取餐订单显示 pickupCode，点击复制
- **取餐码去重**：按 `orderId` 去重，一个订单只显示一个取餐码
- **整体取消**：同一餐别多订单 `Promise.allSettled` 批量取消，余额退回后 `refreshEmployee`
- **下拉刷新**：列表不在顶部时禁用（`canRefresh` 标志），刷新后 `scrollToToday` 滚到今天

目录：[h5/src/api/](file:///d:/文档/enterprise-canteen/enterprise-canteen/h5/src/api/)

| 模块 | 主要接口 | 用途 |
|------|---------|------|
| `index.ts` | axios 实例 + 拦截器 + get/post/put/del 封装 | 全局请求封装，401 处理，Cookie 鉴权 |

### 统一响应约定（ApiResponse）
- `code=200` → 业务成功，拦截器返回 `data` 字段
- `code=401` → 未登录/失效，清登录态跳 `/login`
- 其他 code → 业务错误，toast 提示并 reject
- `blob` 响应直接放行；`config._raw=true` 返回完整 AxiosResponse

## 16. 安全边界

| 边界 | 策略 |
|------|------|
| token 存储 | HttpOnly Cookie（前端不可读），localStorage 仅存 employee 信息 |
| 跨域携带 | `withCredentials: true` |
| 401 处理 | 并发去重，清登录态跳转 |
| 门店隔离 | 后端 checkStoreAccess，员工只能操作自己门店数据 |
| 时间防篡改 | 服务器时间同步（useServerTime），下单前强制刷新 |
| 密码长度 | 最小 8 位（前后端一致） |
| 二维码签名 | HMAC-SHA256 + 后端密钥，7 天有效 |
| 登录后刷新 | 必须刷新员工头像数据，避免 stale localStorage 值 |
| 注销清理 | 清 auth/branding/cart store + 取餐码缓存，避免跨用户泄漏 |
| 图片缓存 | 仅缓存 `/uploads/` 路径；30 天 TTL；版本化 URL 失效 |
| 空值保护 | API 响应数组 `?? []` |
| keep-alive 防重复 | `firstMount` 标志避免 onMounted + onActivated 双重触发 |
| 定时器清理 | onUnmounted 清理 setInterval（navTimer/imageObserver/serverTime） |
