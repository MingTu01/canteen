# H5 订餐端 · 「未订餐用餐」功能特别说明

> 适用版本：H5 订餐端（`h5` 前端）
> 对应页面：`UnsolicitedOrder.vue` · 路由 `/unsolicited-order`

## 一、功能是什么

**未订餐用餐**，也叫「未订餐就餐 / 现场加餐」，是给**没有提前订餐**的员工到食堂现场临时点餐用的。

员工当天没提前订餐，但仍想在食堂吃，可直接在 H5 端进入「未订餐用餐」，选当前餐别现点的菜品下单，由现场打菜人员确认后即可取餐。

它与正常订餐的核心差异：

| 对比项 | 正常订餐 | 未订餐用餐 |
| --- | --- | --- |
| 面向场景 | 当天提前订明天的餐 | 当天现场临时加餐 |
| 截止时间校验 | 需在前一天 15:00 前下单 | **绕过截止时间校验** |
| 防重复校验 | 同一餐次当天只能下一单 | **绕过防重复校验，可多次下单** |
| 下单来源标识 | `orderSource = 0`（正常订餐） | `orderSource = 1`（未订餐用餐） |
| 下单确认 | 直接下单 | **需打菜人员现场确认** |

## 二、入口在哪里

路径：**H5「我的」页面 → 「未订餐用餐」**

## 三、页面长什么样 / 怎么操作

进入页面后，自上而下依次是：

1. **当前餐别信息卡**：显示「当前餐别」「服务器时间」「日期」。
2. **提示条**：橙色提示「下单前请打菜人员确认菜品」。
3. **当前餐别菜品列表**：只展示**当前餐别**的菜品，每道菜可加减数量加入购物车。
4. **底部购物车栏**：有菜品后出现，显示总价与「确认下单」按钮。

### 操作步骤

1. 进入「未订餐用餐」，系统自动判断当前餐别。
2. 在**当前餐别**的菜品中点「＋」加入购物车（其他餐别菜品不可选）。
3. 点底部「确认下单」，弹出确认框，**必须由打菜人员现场核对菜品后**点击「已确认，下单」。
4. 下单成功，跳转订单页，前往取餐。

## 四、关键业务规则（务必理解）

### 1. 当前餐别如何自动判断

系统**以服务器时间为准**（不是手机时间），判断规则：

- 优先匹配食堂配置的**就餐时段**：命中某时段的起止时间即判定为该餐别（1 早餐 / 2 午餐 / 3 晚餐）。
- 若未命中任何时段，则按兜底规则：
  - 11:00 前 → 早餐
  - 11:00–16:00 → 午餐
  - 16:00 之后 → 晚餐
- 页面每 30 秒刷新一次服务器时间，餐别会自动跟随变化。

### 2. 只能选「当前餐别」的菜品

列表只展示当前餐别的菜单菜品，且只允许选择当前餐别下单，避免跨餐别点了不能吃。

### 3. 必须经打菜人员确认

下单前会弹出确认框，展示「当前餐别 / 菜品数量 / 合计金额」，并友情提示请打菜人员确认。确认后才会真正提交订单。

### 4. 绕过截止时间与防重复

后端判断 `orderSource = 1` 时，会**跳过两处常规校验**：

- 跳过「次日订单需在前一天 15:00 前下单」的截止校验；
- 跳过「同一员工同一日期同一餐次只能下一单」的防重复校验。

> 因此未订餐用餐可以当天现场多次下单、也可以超过截止时间补点，这是它与正常订餐最大的区别。

### 5. 只展示今天，不跨天

页面只加载**今日**菜单，判断的是**当下**该吃的餐别，属于"现在+现场"的即时点餐，不提供跨天预订。

## 五、注意事项 / 使用建议

- **请务必先与打菜人员确认**再点「确认下单」，确认后订单即生成并扣费。
- 当前餐别没有配置菜单或无菜品时，页面会提示「当前餐别暂无可选菜品」。
- 余额不足或菜品下架等异常，会在下单时由后端拦截并提示。
- 该功能默认开放；若食堂不希望员工随意现场加餐，可在管理端评估后关闭该入口或相关菜品。

## 六、与「正常订餐」的选用建议

| 场景 | 建议使用 |
| --- | --- |
| 提前规划、预订明天或后天的餐 | 正常订餐（首页选日期订餐） |
| 今天临时没订、现场想吃 | **未订餐用餐** |
