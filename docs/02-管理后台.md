## 1. 项目定位

集团级企业智慧食堂的管理后台，面向超级管理员、门店管理员、财务、厨师长、店长 5 类管理角色，提供菜品/菜单/订单/员工/采购/库存/报表/对账/备份等全功能管理能力。

- **多角色 RBAC**：7 类角色精细化的菜单/路由/按钮权限控制
- **多门店切换**：超级管理员可切换管理任意门店，其他角色仅本店
- **统一设计系统**：Tailwind 4 设计令牌 + Element Plus 主题覆盖 + MiSans 字体
- **响应式布局**：桌面侧边栏 + 移动 Drawer 自适应

## 3. 鉴权策略

### 3.1 token 存储
- token 由后端写入 **HttpOnly Cookie**（`auth_token`），浏览器自动随请求携带
- `withCredentials: true` 必需（跨域携带 Cookie）
- `localStorage['auth']` 仅缓存 admin 信息与"已登录"标志（pinia persist 插件同步），**不存储 token**

### 3.2 401/403 拦截
- 响应拦截器统一处理：HTTP 200 + code=401 或 HTTP 401
- **401 并发去重**：`isRedirecting` 标志，多个并发 401 只允许第一个触发清理+跳转
- 登录请求自身不清状态/跳转，仅 toast 提示
- 清空登录态并跳转 `/login`（带 redirect query）

## 4. 权限系统

### 4.1 角色定义

| 角色 ID | 常量 | 名称 | 范围 |
|---------|------|------|------|
| 0 | `ROLE_EMPLOYEE` | 员工 | H5/小程序端（不进入管理后台） |
| 1 | `ROLE_SUPER_ADMIN` | 超级管理员 | 可跨门店 |
| 2 | `ROLE_STORE_ADMIN` | 门店管理员 | 仅本门店 |
| 3 | `ROLE_TERMINAL` | 终端 | 扫码设备（不进入管理后台） |
| 4 | `ROLE_FINANCE` | 财务岗 | 报表 + 充值 |
| 5 | `ROLE_CHEF` | 厨师长 | 订餐汇总 + 菜品 |
| 6 | `ROLE_STORE_MANAGER` | 店长 | 全店管理，不可删数据 |

### 4.2 菜单访问规则（RBAC）

通过路由 `meta.roles` 与侧边栏 `menuItems[].roles` 双重控制：

| 菜单 | 允许角色 |
|------|----------|
| 数据总览 | 1, 2, 4, 5, 6（全员管理岗） |
| 菜品管理 / 菜单管理 / 订餐汇总 / 供应商 / 采购 / 库存 | 1, 2, 5, 6 |
| 订单管理 / 员工管理 / 部门 / 就餐时段 / 通知 / 反馈 / 团体订餐 | 1, 2, 6 |
| 报表 / 日终对账 / 关店对账 / 充值记录 | 1, 2, 4, 6 |
| 账号管理 / 备份恢复 / 操作日志 | 1, 2 |
| 食堂管理 / 系统设置 | 1（仅超管） |

侧边栏 `visibleMenuItems` 通过 `authStore.hasRole(...item.roles)` 过滤显示；路由守卫 `beforeEach` 在角色不匹配时调用 `authStore.clearState()` 并跳转登录页。

### 4.3 权限工具（permission.ts）

提供函数式权限判断（非自定义指令 `v-permission`）：
- `currentRole()` / `currentStoreId()` — 当前角色/门店
- `isSuperAdmin()` / `isStoreAdmin()` / `isFinance()` / `isChef()` / `isStoreManager()` / `isAdmin()`
- `hasPermission(roles[])` — 是否拥有指定角色之一
- `canAccessStore(targetStoreId)` — 门店访问校验（超管任意，其他仅本门店）
- `canAccessRoute(routeMetaRoles)` — 路由守卫用

`authStore` 内置语义化方法：`canViewFinance()`、`canManageDish()`、`canManageProcurement()`、`canManageSystem()`、`canSettle()`。

### 4.4 门店切换（超管专属）

`useStoreSwitch` composable 复用于 Report、Settlement、Backup、Settings、Store 5 个视图：
- `isSuperAdmin` / `stores` / `selectedStoreId` / `activeStoreId` / `fetchStores()`
- 非超管时 `selectedStoreId` 保持 `undefined`，`activeStoreId` 回退到 `authStore.storeId`
- 超管首次拉取自动选中第一家门店
- **关键约束**：超管未选店时各业务页 `sid` 返回 `null`（不静默回退 `storeId=1`），页面展示"请先选择食堂"占位提示，且不发起 API 请求

## 6. 各页面关键功能

> 通用约定：
> - 列表 API 返回 `T[]` 或 `PageResult<T>`，组件统一用 `normalizeList()` 兜底
> - 空值保护用 `?? []` / `?? 0`
> - 模态弹窗 `:close-on-click-modal="false"`（点击遮罩不关闭，仅按钮关闭）
> - 错误由 axios 拦截器统一 `ElMessage.error` 提示

### 6.1 登录页
- 账号密码表单 + Element Plus 表单校验
- 登录成功跳转 `redirect` query 或 `/dashboard`
- 已登录访问 `/login` 自动重定向 `/dashboard`

### 6.2 数据总览
- 关键指标卡片（StatCard）+ ECharts 图表
- 角色 `[1,2,4,5,6]` 可见

### 6.3 菜品管理
- 菜品 CRUD、分类管理、图片上传（ImageUploader + imageCompress 压缩）
- 批量上下架、批量改分类、批量软删
- 回收站（还原 / 物理删除）
- 角色 `[1,2,5,6]`

### 6.4 菜单管理
- 按日期规划每日菜单（早/午/晚餐），关联菜品
- 菜单复制（源日期 → 目标日期，可选 overwrite）
- 角色 `[1,2,5,6]`

### 6.5 订单管理
- 订单列表、状态流转（待取餐/已完成/已取消）、筛选、详情
- Excel 导出含"订单来源"字段
- 角色 `[1,2,6]`

### 6.6 订餐汇总
- 按餐次/菜品汇总订餐数量，供厨师备餐
- 角色 `[1,2,5,6]`

### 6.7 员工管理
- 员工档案 CRUD、余额管理（充值/扣款）
- 批量导入：**按卡号去重**，后者覆盖前者
- **替换头像时删除旧文件**避免孤儿文件
- 上传头像时已有头像显示"已存在，将替换"提示
- 余额预警名单 + 统计
- CSV 导出（UTF-8 BOM，防公式注入）
- 角色 `[1,2,6]`

### 6.8 部门管理
- 部门层级 CRUD
- 角色 `[1,2,6]`

### 6.9 就餐时段配置
- 按餐次（早/午/晚）管理时段卡片视图
- **特色**：实时状态（进行中/未开始/已结束）每 30 秒刷新
- 时段冲突校验（同餐次重叠拒绝）
- 结束时间必须晚于开始时间
- 删除二次确认
- 角色 `[1,2,6]`

### 6.10 通知管理
- 通知 CRUD，类型（系统/公告/活动）
- 有效期管理（默认 30 天，自动下架）
- 展示状态 `displayStatus`（pending/active/expired/offline）由后端计算
- 角色 `[1,2,6]`

### 6.11 供应商管理
- 供应商 CRUD（名称/联系人/电话/品类/地址/状态）
- 品类下拉可输入（米面粮油/蔬菜/肉类等）
- 角色 `[1,2,5,6]`

### 6.12 采购管理
- 采购单工作流：创建（选供应商 + 多行明细）、查看详情（Drawer）、入库确认（状态 1→2）、取消
- 状态字典：1 待入库 / 2 已入库 / 3 已取消
- 入库二次确认，入库后不可修改
- 筛选：状态 + 日期范围
- 角色 `[1,2,5,6]`

### 6.13 库存食材
- 食材 CRUD + 库存管理（入库 `inbound` / 出库 `outbound` + 备注）
- 低库存预警：`isLowStock = stockQty < minStock`
- 数量必须 > 0 校验
- 角色 `[1,2,5,6]`

### 6.14 反馈评价
- 员工反馈/评分查看与处理
- 管理员回复
- 角色 `[1,2,6]`

### 6.15 团体订餐
- 会议/团体用餐订餐管理
- 状态：1 待确认 / 2 已确认 / 3 已取消 / 4 已完成
- 角色 `[1,2,6]`

### 6.16 报表统计
- 6 类报表：营业、财务、拥挤度、员工消费、环比(MoM)、同比(YoY)
- ECharts 可视化（useEcharts composable）
- 角色 `[1,2,4,6]`

### 6.17 日终对账
- 按日期核对当日订单/营业额/退款/充值/新增员工，确认后归档
- 顶部 6 个 StatCard（订单总数/已支付/已取消/营业额/退款/充值）+ 次级（新增员工/净流水）
- 菜品销量 TOP5 排行榜（前三名高亮主色）
- 历史对账记录分页表格
- 确认操作二次确认，确认后不可重复
- 角色 `[1,2,4,6]`

### 6.18 关店对账
- 多步对账流程：生成对账 → 确认对账 → 关店（锁定）
- 状态机：未对账(null) → 待对账(1) → 已对账(2) → 已关店(3)
- 按钮可用性由状态驱动（`canGenerate`/`canConfirm`/`canClose`）
- 5 个 StatCard（订单数/营业额/退款/充值/消费）+ 订单状态对比表 + 充值明细
- 历史最近 30 天列表，点击行查看详情
- 超管门店切换（useStoreSwitch）
- 角色 `[1,2,4,6]`

### 6.19 充值记录
- 充值流水查询
- 角色 `[1,2,4,6]`

### 6.20 食堂管理
- 食堂档案 CRUD（名称/地址/电话/logo/品牌资源）
- 自动生成 8 位安全码（排除易混淆字符 0/O/1/I/l）
- 重置安全码（重置后旧终端需重新绑定）
- 仅超管 `[1]`

### 6.21 账号管理
- 管理员账号 CRUD、角色分配
- 门店管理员仅能管理本店非超管
- 角色 `[1,2]`

### 6.22 系统设置
- 5 个 Tab：门店信息 / 支付与余额 / 通知配置 / 账户安全 / 系统信息
- **门店信息**：超管可切换门店编辑（名称/地址/电话）
- **支付与余额**：`balance_min_warning`、`allow_negative_balance`、`recharge_min_amount`、`recharge_max_amount`（仅超管可改）
- **通知配置**：`notification_default_duration_days`(1-365)、`notification_auto_expire`
- **账户安全**：修改密码（旧密码 + 新密码 ≥8 位 + 确认密码，新密码不能与旧密码相同）
- **系统信息**：版本号/构建时间/服务状态(UP/DOWN)/数据库状态/迁移历史
- 仅超管 `[1]`

### 6.23 备份恢复
- 数据库备份与恢复
- 门店级 `store_id` WHERE 隔离 + 全量备份
- 恢复前自动快照（便于回滚）
- 角色 `[1,2]`

### 6.24 操作日志
- 管理员操作记录查询
- 筛选：操作关键词 + 状态（成功/失败）
- 字段：ID/操作/方法/参数/IP/状态/错误信息/时间
- 默认每页 20 条，可选 20/50/100/200
- 角色 `[1,2]`

## 9. 路由守卫

- `beforeEach`：nprogress 启动；`requiresAuth` 且未登录跳 `/login`（带 redirect query）；已登录访问 `/login` 跳 `/dashboard`；`meta.roles` 不匹配时 `clearState()` + 跳登录（避免死循环）
- `afterEach`：nprogress 完成；设置文档标题 `${title} - 企业智慧食堂`
- `scrollBehavior`：返回 savedPosition 或 `{ top: 0 }`

## 10. 其他系统级约定

### 10.1 侧边栏状态

- `money.ts`：money() 金额格式化
- `permission.ts`：权限工具

## 11. 安全边界

| 边界 | 策略 |
|------|------|
| token 存储 | HttpOnly Cookie（前端不可读），localStorage 仅存 admin 信息 |
| 跨域携带 | `withCredentials: true` |
| 401 处理 | 并发去重，清登录态跳转 |
| 角色隔离 | RBAC 路由守卫 + 侧边栏过滤 + 后端 checkStoreAccess |
| 门店隔离 | 非超管仅本店；超管未选店不发起请求 |
| 弹窗关闭 | `:close-on-click-modal="false"`（点击遮罩不关闭） |
| 密码长度 | 最小 8 位（前后端一致） |
| 图片上传 | PNG 保留 alpha 通道；压缩到 300x300 / JPEG 0.8 |
| 空值保护 | API 响应数组 `?? []`，数值 `?? 0` |
