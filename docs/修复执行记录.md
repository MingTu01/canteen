## 二、新需求 1：未订餐用餐手续费

### 业务规则
- 手续费按「门店 × 餐别（早/中/晚）」配置，可整体启用/停用，每餐别独立金额（0–9999 元，2 位小数，0 表示该餐别不收）。
- 仅 `orderSource=1`（未订餐用餐）订单收取，按单收取（与菜品数量无关）；正常订餐恒为 0。
- **金额模型**：`total_amount = 菜品小计 + service_fee`（service_fee 新增字段记录手续费部分）；扣款按 total_amount，取消订单全额退款（含手续费）。
- 对账/看板按 total_amount 统计，手续费自动纳入营业额。

### 配置项（store_config，K-V 表无需改结构）
| key | 默认值 |
|---|---|
| unsolicited_fee_enabled | false |
| unsolicited_fee_breakfast / lunch / dinner | 0 |

### 改动清单
**后端**
- `V24__order_service_fee.sql`（新建）：order 表加 `service_fee DECIMAL(10,2) NOT NULL DEFAULT 0`；schema-h2.sql 同步（测试兼容）
- `Order.java`：新增 `serviceFee` 字段
- `StoreConfigController.java`：4 个新 key 进白名单与默认值表；公开读取端点 `/api/store-config/order` 自动带出（H5 免登录可读）
- `OrderService.createOrder`：`getUnsolicitedServiceFee(storeId, mealType)`（读顺序 store_config → sys_config → 默认；enabled 非 true / 解析失败 / 负数 → 0，上限 9999）；扣款与订单金额用 `payAmount = 菜品小计 + serviceFee`

**admin-web**
- `components/UnsolicitedFeeDialog.vue`（新建）：启用开关 + 早/中/晚三个金额输入，读写走 store-config API，超管未选门店时禁用
- `OrderManagement.vue`（订单管理）：搜索区「导出Excel」旁新增「手续费设置」按钮；表格新增「手续费」「订单总额」列（订单首行显示）；详情抽屉新增「订单来源」「手续费」行，有手续费时总额显示「实付总额 + 菜品 ¥X + 手续费 ¥Y」拆分；**Excel 导出新增「手续费」「订单总额」两列**（订单首行非空，避免求和重复计算）
- `MenuManagement.vue`（菜单管理）：「订餐配置」旁新增「手续费设置」按钮，复用同一弹窗
- `api/types.ts` / `api/system.ts`：Order.serviceFee、OrderConfig 新字段

**H5**
- `UnsolicitedOrder.vue`（未订餐用餐页）：进入时拉取门店配置；启用且当前餐别金额>0 时显示醒目红色提示条「未订餐用餐将按单收取手续费 ¥X」；底部金额、购物车弹层合计、打菜员确认弹窗均展示「含手续费」的应付总额

## 三、新需求 2：X86 终端问题

### 2a. 部分设备点击输入框/筛选按钮整体闪烁 —— 根因与修复
根因是**低端集显设备上的 GPU 重绘/合成层重建**（高性能独显设备不触发，与「部分设备闪、部分不闪」现象吻合）：

| 根因 | 位置 | 修复 |
|---|---|---|
| `backdrop-filter: blur(8px)`（GPU 重绘开销最大） | PickupInfo.vue 取餐卡片 | 删除，背景加深至 rgba(0,0,0,0.62) 保持遮罩效果 |
| 输入框 focus 时 box-shadow 0→3px 过渡（触发合成层重建） | AdminEntryZone.vue 密码框 | 只过渡 border-color（与 OrderQueryModal 既有规避方案一致） |
| `transition: all`（意外属性重绘） | Settings.vue 3 处按钮 | 收窄为实际变化的属性 |
| `filter: drop-shadow`（GPU 涂层开销） | OrderStandby / PickupStandby 扫码图标 | 删除 |
| 动画与 transition 叠加同元素（持续重绘） | OrderStandby / PickupStandby 扫码按钮 | 移除 transition，保留 transform/opacity 脉冲动画 |
| 启动白闪：body 白底 vs 应用深底 + QWebEngineView 默认白底 | index.html / style.css / src-python/main.py | body/html 背景改 #0e1115；`page.setBackgroundColor(QColor('#0e1115'))` 消除加载期白屏 |

### 2b. 订单汇总菜品字体放大
OrderQueryModal 汇总视图：菜名/数量由 clamp(10px,0.9vw,12px) 提升至 **clamp(15px,1.3vw,17px)**（行距同步调整）；小票详情菜名提升至 clamp(15px,1.4vw,17px)。

## 六、部署注意（本次改动引入）

1. **数据库**：新增 V24（order.service_fee）、V25（索引）两个 Flyway 迁移，重启自动执行，无需手工操作。
2. **终端 token 策略**：有效期 365→30 天。**存量已绑定终端会在 30 天内陆续触发自动续期**；超过 30 天未开机的终端需重新扫码绑定（一次性影响，换来泄露风险窗口缩短 12 倍）。
3. **CORS**：未配置 `CORS_ALLOWED_ORIGINS` 的部署，跨域携带 Cookie 的调用将被浏览器拒绝（同源 nginx 部署与终端 Authorization 头调用不受影响）。若有自定义跨域域名 + Cookie 的场景，必须显式配置白名单。
4. **报表/对账口径**：营业额统一按订餐日期。切换日当天的历史对账数据若已生成，数值可能与新口径存在次日订单差异，属预期（可重新生成待对账状态的记录）。
5. **升级包发布**：建议后续在 VERSIONS.json 中提供 sha256 字段，终端将自动启用强校验。
